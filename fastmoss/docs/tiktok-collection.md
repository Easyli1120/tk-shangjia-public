# TikTok Shop 批量采集

在数据上传页粘贴 1–3000 条商品链接，点击“开始采集”。换行或空格分隔；相同市场、相同商品 ID 在一次提交中自动去重。站点从链接的 region 参数或地区路径识别，未注明时使用美国站。提交立即入队；已有任务时依次处理，无须每 100 条手动继续。

Excel / CSV 商品文件上传成功后，服务端自动创建采集任务，读取这一批仍在竞品库中的商品，采集页面返回的全部图组、商品信息、销量和 SKU。无需在文件记录中再点击按钮；文件记录只保留删除操作。任务建立后自动展开“采集进度”，显示当前商品、图片已保存 / 已发现数量和每条缺失原因；返回数据上传页时，有进行中的任务也会自动展开。重复上传同一文件时复用已有任务，不重复采集；店铺文件不创建商品采集任务。文件启动的采集保留独立采集快照，删除该文件来源时一并取消、删除关联采集，迟到结果不再保存。

任务运行在本机后台服务，关闭网页不停止任务。电脑睡眠、断网、关机期间无法采集；服务重启后继续未完成的商品。请保持电脑唤醒。

- 点击“开始采集”后直接读取商品页并下载页面返回的全部商品图、规格图、详情图和尺码表，不限于上架时的九张主图；下载到本地后才算保存完成。
- 颜色、款式、尺码等保留原始属性及 SKU 组合，保留逐 SKU 售价、原价、币种和库存字段。
- 商品信息保留原始标题、文字详情和属性；页面销量保留原始显示值及统计口径，在竞品库的商品详情中查看。销量未返回时显示“未知”，不推算近 7 天或近 28 天销量，也不覆盖导入表格的销售指标。
- 类目随页面资料保存；类目缺失或未确认最末级，不影响采集完成，也不会因此补采。图组采集不等待类目识别；保存后通知独立的后台类目任务检查新资料。上架时的类目要求独立校验。
- 已采集资料进入竞品库；原有手动改名、改价、隐藏图片和 SKU 操作保留。
- “采集完成”仅表示该次页面返回的数据通过字段及图片校验，不代表可以验证平台未公开的数据或所有地区/账号的价格。

每条保存后立即打开下一条。人工验证期间队列停在当前商品，若验证窗口断开，先恢复这条商品。不设置整队冷却；访问限流时继续处理后续链接，单条重试仍最多 3 次。验证码继续在原窗口交由用户完成。

采集使用一个持续运行的普通 Chrome 进程、独立本机配置和同一个标签页。后续商品复用这个会话，不在人工验证与后台采集之间切换无头浏览器。调试连接仅监听本机回环地址，不使用用户日常浏览器配置。

遇到验证码时，采集窗口会显示到前台，上传页显示“等待你完成验证码 · 通过后自动继续”。程序保持当前标签页，用户直接在该窗口完成验证；检测到对应商品原始数据后自动保存，随后直接采集下一条，无需关闭窗口、点击继续或重新提交。验证等待有持续心跳，不计入单条采集超时或消耗重试次数。请勿在另一个普通浏览器中验证，因为它不是采集会话。仍不能保证 TikTok 永远不再要求验证。

服务重启优先重新连接原有采集 Chrome；窗口被关闭时可重新打开同一配置并恢复任务，但平台可能再次要求验证。关闭上传页不影响队列。验证码等待时可停止任务。普通页面加载限时 30 秒，单条非人工等待时间限时 300 秒，图片下载每个 CDN 地址限时 12 秒。普通失败最多尝试 3 次，各种错误重试均不设置额外倒计时，优先处理未尝试的新链接。仅类目缺失或未能确认末级时，只要其余资料和图片保存完整，即标记“采集完成”，不需要补采。

可暂停/继续、停止任务、补采未完成、导出未完成链接。每条任务提供“删除本次任务”：确认后隐藏该任务，停止尚未完成的采集，并将该任务关联的竞品库商品移入“数据恢复”。同一商品重复出现在其他任务时也会从竞品库移除；其他商品和店铺中已经发布的商品不受影响。可在“设置 → 数据恢复”恢复商品，任务不会因此重新开始；删除后的延迟采集结果不会重新保存。暂停让当前商品处理结束；停止后不再保存该次正在执行的结果，已保存商品保留。普通单条异常和缺失类目不会暂停整批任务；验证码会明确等待人工处理，通过后自动恢复。

删除商品或上传来源时，同时取消相关采集；类目任务在每件处理前、发起推荐前和保存前检查商品是否仍有效。已经发出的请求返回后不会保存旧结果，也不会继续后续匹配。恢复商品不会恢复被取消的采集；重新提交链接会使用新任务重新保存图组、商品资料、销量和 SKU，保留人工编辑。删除来源后若商品还有其他来源，则保留其他来源的数据。

实现由 `collection_queue.py`（SQLite 持久队列）、`browser_capture.py`（共享浏览器会话）和 `tiktok_collect.py`（独立限时子进程）组成。仍保留旧版采集接口的 410 响应，避免过期客户端误启动旧采集逻辑。新 API 使用 `/api/tiktok/`。

验证命令：`PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v`。测试涵盖 3000 条上限、100 条连续运行夹杂异常、失败重试上限、恢复、取消后的过期结果、请求幂等、无整队冷却、地区不售立即完成、验证后立即继续、类目可选、历史状态修正以及原有商品编辑。模拟队列通过不等同于 100 条真实 TikTok 商品的成功率测试。

恢复机制：服务重启时优先保留正在验证的原标签页，不重新导航；连接会话失效时最多尝试 2 次重新附着同一标签页。页面加载事件已错过时先读取浏览器里的原始文档；若平台不缓存该文档且页面没有验证码，立即重载一次以恢复原始 SKU 数据。验证码消失后第一次检查即恢复读取，不额外等待 15/30 秒；验证码存在时仍每秒检查，状态不变时每 15 秒写一次数据库，减少长时间等待的磁盘写入。图片清单为空或没有保存主图时不会标记完整。

图片下载最多同时进行 2 张，保持原始图组顺序；单张失败不影响其他图片，补采复用已保存的有效图片。每张图片所有重定向共用 12 秒预算，单条商品为结果落盘预留 15 秒，人工验证等待不消耗该预算。

页面明确显示“此国家或地区未提供的商品”时，在页面检查中立即结束当前条目，单独显示为“本地区不售 · 未取得资料”，计入已处理、不计入资料已保存，不自动补采。竞品库保留商品 ID、来源链接和地区不售标记，不使用推荐商品作为目标商品资料，也不虚构图片或 SKU；已有资料保留。未能解析商品 ID 的短链接仍保留在任务明细中。
