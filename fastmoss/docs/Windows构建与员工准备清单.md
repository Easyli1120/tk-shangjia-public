# Windows 构建与员工准备清单

## 当前交付边界

Windows 安装包由 Windows 构建机生成，包含 Python、程序依赖、采集浏览器和中英文 OCR。当前构建脚本的输出文件为 `TKShangjia-Setup-2026.11.24-x64.exe`。公开安装包以 [GitHub Releases](https://github.com/Easyli1120/tk-shangjia-public/releases) 为准，也可以自行构建。支持 Windows 10 1809+ / Windows 11 x64，安装依赖可离线完成，实际联网功能仍需要网络和账号授权。

自动验收使用 Windows Server 2022，检查独立安装后的组件和启动流程。Windows 10/11 实机和真实店铺流程按文末清单验收。

固定地址只保证软件成功启动后的本机入口一致。`127.0.0.1` 指使用者自己的电脑；授权浏览器必须与软件在同一台电脑上，软件须保持运行。旧应用如登记了其他端口，需要在 Partner Center 保存新的完整地址（含末尾 `/`）并重新授权。原 2026.11.20 安装包仍会自动换端口，需换用新版。TikTok 是否接受本地 HTTP 以及真实授权结果仍需在使用者账户验证。

## 构建电脑操作（开发或发布人员，仅一次）

1. 使用 Windows x64，安装 Python 3.12 x64 和 [Inno Setup 6.4.3](https://github.com/jrsoftware/issrc/releases/tag/is-6_4_3)。CI 固定版本并校验下载文件的 SHA-256；自定义安装位置可通过 `TKSHANGJIA_ISCC` 指向 `ISCC.exe`。
2. 取得完整项目，打开 PowerShell，进入项目目录。
3. 执行 `fastmoss\packaging\build-windows.ps1`。它安装依赖、运行全部回归、下载固定版本的浏览器和 OCR 组件、打包程序、运行独立程序测试，再生成安装包。构建电脑需要联网，员工安装时无需重新下载组件。
4. 产物：项目根目录 `release\TKShangjia-Setup-2026.11.24-x64.exe`，以及 `fastmoss\dist\TKShangjia` 可运行目录。
5. 构建脚本输出 SHA-256；如要正式分发，可使用组织拥有的证书签名。当前没有代码签名证书，不能声称 Windows 已验证发布者。

构建不包含任何开发者数据库、.env、图片库、浏览器配置和凭证。程序携带 Python 和所需库；员工无需安装 Python、Node、Inno Setup。软件网页通过 Windows 默认浏览器打开；采集优先使用包内的 Chrome for Testing。OCR 使用包内的 Tesseract 和英文、简体中文模型，不依赖 Windows OCR 语言包。第三方组件的下载来源和 SHA-256 保存在 `dependencies.json`。

仓库的 `.github/workflows/windows-build.yml` 在 Windows runner 构建并执行静默安装测试。构建和安装后分别检查独立启动、中文路径、端口冲突、重复打开、凭证加密、内置 OCR、内置浏览器与采集子进程；安装测试还检查桌面快捷方式及卸载后数据保留。启动测试仅保留 Windows 系统目录在 PATH 中，排除 Python、Node 和外部 OCR 命令。CI 不等于真实员工电脑和真实店铺的完整验收。

## 员工需要准备的资料

- 自己店铺的所有者账号、所在市场、本土 / 跨境类型；员工子账号不一定具备开发者资格。
- TikTok 平台认可的 Seller Developer 资格与已完成的主体资料。
- 自己创建的 Custom App、App Key、App Secret，以及 Copy authorization link。
- 商品管理与仓库所需权限；跨境使用相应全球商品及类目权限。
- 平台要求时，自己控制的 HTTPS 域名、受信任证书及回调转发方案。
- 实际发货仓库、商品售价库存、包装重量尺寸、类目资质及有权使用的图片和内容。

商品标题和详情直接显示采集到的竞品英文，由运营人员修改英文后提交，不调用翻译服务，也不需要配置 AI 模型。历史中文编辑记录保留，切换英文表单时优先带入采集原文；已保存的人工英文修改会保留。安装包不携带开发者的 AI 密钥。自动尺码表识别不可用时，可以上传现成尺码图并手动核对。

## 必须在 Partner Center 手动完成

账号注册 / 登录、主账号验证、主体或资格审核、选择正确应用类型与市场、应用创建、申请 API 权限、保存并发布 Redirect URL 和权限变更、完成平台要求的应用审核 / 启用，以及在官方页面确认店铺授权。

软件自动完成：独立数据目录、固定 8765 主网页端口、本地回调监听、默认浏览器打开、State 校验、Code 换取凭证、凭证加密保存、到期前请求刷新、读取店铺与商品查询。无需复制 Token、修改代码或连接开发者电脑。

完整的 13 步员工教程位于软件「店铺管理」及 `static/employee-guide.html`。操作截图仅保留本机，不随源码或安装包分发，以免泄露店铺和应用信息。员工在步骤13复制授权链接、App Key、App Secret，粘贴到首页三个输入框并点击连接，再在 TikTok 页面确认授权。

## Windows 发布前验收

- 在没有 Python / Node 的新 Windows 用户或新机安装；中文目录、默认浏览器、卸载后数据保留。
- 主网页及步骤9地址固定为 `http://127.0.0.1:8765/`；忽略旧运行记录及 `FASTMOSS_PORT` 中的其他端口。8765 被占用时提示并退出，不自动换端口；重复启动打开固定地址的原实例；旧版仍占用其他端口时提示先退出旧版。不同电脑 / 用户数据、SKU、图片和密钥独立。
- DPAPI 原用户重启读取正常；复制凭证到不同用户 / 机器后不能复用。
- 内置浏览器的真实 TikTok 采集、人工验证续跑、图片编辑和真实商品图片 OCR；识别结果仍需人工核对。
- 真实合资格测试账号从空配置完成授权、回调、读取店铺、重新授权、刷新、解除本机绑定。
- Development Shop 或获准测试环境执行图片上传、`AS_DRAFT` 创建 / 编辑和状态查询；发布测试须有明确的测试环境与确认。
- 如果正式平台拒绝本地 HTTP，单独测试自有 HTTPS 回调完整链路及专用回调端口变化后的配置更新。
